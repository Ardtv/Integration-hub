# Допущения и открытые вопросы

Код написан без ответов заказчика по четырём темам. Ниже каждое допущение: что предположено, где меняется и как проверить. Пока допущение не проверено, соответствующее звено держите в тестовом режиме или выключенным.

## Допущения

| № | Тема | Что предположено | Где меняется | Как проверить |
|---|---|---|---|---|
| 1 | Заявка СДЭК | Заказ создаётся через API СДЭК v2 (`POST /orders`, тип «интернет-магазин»). Параметры, которые делают заявку фулфилментной, неизвестны | `CDEK_ORDER_EXTRA_JSON`, `CDEK_SHIPMENT_POINT` или `CDEK_FROM_LOCATION_JSON` | Сравнить тело запроса из панели с образцом заявки от Валентины |
| 2 | Тарифы СДЭК | Отдельный тариф для двери и для ПВЗ, значений по умолчанию нет | `CDEK_TARIFF_DOOR`, `CDEK_TARIFF_PVZ` | Взять коды тарифов из образца заявки |
| 3 | Наложенный платёж | Сумма к оплате передаётся в цене каждой позиции (`payment.value`). Бюджет сделки обязан равняться сумме товаров | `AMO_STRICT_SUM=false` отключает проверку суммы | Одна заявка в тестовом контуре СДЭК |
| 4 | Отправки в РФ | Валюта и таможенные поля не заполняются | `CDEK_ORDER_EXTRA_RU_JSON` | Уточнить у СДЭК, поддерживает ли договор наложенный платёж на международных отправлениях |
| 5 | Вес и габариты | Вес товара из справочника, иначе `CDEK_DEFAULT_ITEM_WEIGHT_G`; одна коробка с габаритами из `.env` | Вкладка «Товары», `CDEK_BOX_*` | Сверить с реальной упаковкой |
| 6 | Момент отгрузки | Отгрузкой считается первый из статусов СДЭК в `CDEK_SHIPPED_CODES` | `CDEK_SHIPPED_CODES` | Посмотреть историю статусов образца заявки: какой статус означает «уехал со склада» |
| 7 | Возврат | Возвратом считается статус `NOT_DELIVERED` | `CDEK_RETURNED_CODES` | Уточнить, какими статусами СДЭК отмечает возврат на склад фулфилмента |
| 8 | Списание IIKO | Документ списания создаётся запросом `writeoff_document/create` из тестового скрипта Этапа 2 | `IIKO_WRITEOFF_ENABLED`, `IIKO_STORE_ID`, `IIKO_EXPENSE_ACCOUNT_ID`, `IIKO_DEFAULT_UNIT_ID` | **Риск:** в ТЗ отмечено, что нужного запроса в iikoCloud API может не быть и потребуется iikoServer. Проверить одним списанием на тестовом складе |
| 9 | Возврат IIKO | Не реализован: документ с менеджером IIKO не согласован. Менеджер получает задачу оприходовать вручную | `src/services/documents.ts`, метод `returnIiko` | Встреча с менеджером IIKO |
| 10 | Документы 1С | Стандартный интерфейс OData: `Document_РеализацияТоваровУслуг` и `Document_ВозвратТоваровОтКлиента`, табличная часть «Товары» с полями `Номенклатура_Key`, `Количество`, `Цена`, `Сумма`, шапка с `Контрагент_Key` и `Комментарий`, `Posted: false` | Переменные `API_1C_*`, дополнительные поля шапки в `API_1C_DOCUMENT_EXTRA_JSON` | Создать один черновик в тестовой базе 1С. Названия полей зависят от конфигурации |
| 11 | Контрагент 1С | Ищется по наименованию: «Розница» для КЗ, «Розница РФ» для РФ | `API_1C_COUNTERPARTY_*`, либо сразу GUID в `*_REF` | Бухгалтер подтверждает наименования |
| 12 | Товары amo | Цена и артикул читаются из полей каталога amo с кодами `PRICE` и `SKU`, количество из привязки товара к сделке | `src/gateways/real.ts`, метод `getDeal` | `npm run amo:discover` и одна сделка в тестовом режиме: цены видны в карточке сделки в панели |
| 13 | Значения списков amo | «Способ отправки», «Страна», «Тип доставки» распознаются по тексту варианта | `src/services/intent.ts` | Создать поля скриптом `amo:setup`: варианты совпадут |
| 14 | Формат вебхука amo | Принимаются и форма `x-www-form-urlencoded`, и JSON | — | Первый живой вебхук: событие появится в панели |
| 15 | Караганда | Хаб только оставляет примечание. Списания в IIKO и документов в 1С по таким сделкам нет | `src/services/orchestrator.ts` | Решение заказчика |
| 16 | Повторная заявка после отказа СДЭК | Номер заказа в СДЭК равен ID сделки. Если СДЭК не допускает повтор номера после отклонённой заявки, новая заявка не создастся | `src/services/cdek-order.ts`, поле `number` | Проверить в тестовом контуре: отклонённая заявка, исправление, повтор |
| 17 | Маркетплейсы | Воронки Ozon, Wildberries, Kaspi со схемы Miro не обслуживаются: по ТЗ Этапа 2.1 они остановлены | `AMO_PIPELINE_IDS` ограничивает обслуживаемые воронки | Решение заказчика |
| 18 | Цена в справочнике IIKO | Сохраняется как пришла, в расчётах не участвует: суммы берутся из сделки amo | `connectors/iiko/sync-menu.js` | Уточнить валюту цен внешнего меню |

## Что запросить у заказчика

1. Номера одной-двух заявок фулфилмента от Валентины — закрывает допущения 1, 2, 6, 7.
2. Встречу с менеджером IIKO: списание, возврат, склад, доступ к iikoServer — допущения 8 и 9.
3. Тестовую базу 1С и бухгалтера: вид документов, названия полей, контрагенты, правильные карточки товаров — допущения 10 и 11.
4. Решения по Караганде, отправкам в РФ и маркетплейсам — допущения 4, 15, 17.

## Чего в этой версии нет

- Отмены заявки СДЭК из amo: хаб заявки не отменяет.
- Автоматического прихода в IIKO при возврате.
- Нескольких коробок в одном заказе.
- Автоматического заполнения карточек 1С в справочнике товаров.
