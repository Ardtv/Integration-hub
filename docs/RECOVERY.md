# Резервные копии и восстановление

## Что копируется

`scripts/backup-db.sh` раз в сутки (cron, 03:30) делает `pg_dump` базы хаба в `BACKUP_DIR` и хранит `BACKUP_KEEP_DAYS` дней. Если задан `BACKUP_REMOTE`, копия уходит за пределы сервера через rclone или scp.

**Задайте `BACKUP_REMOTE`.** Копия, которая лежит только на том же сервере, пропадёт вместе с ним.

`.env` в резервную копию не входит. Храните его отдельно: в менеджере паролей.

## Проверка копии

```bash
ls -lh /var/backups/integration-hub | tail -3
pg_restore --list /var/backups/integration-hub/<файл>.dump | head
```

## Восстановление базы на том же сервере

```bash
pm2 stop all
sudo -u postgres psql -c "DROP DATABASE instinct_db;"
sudo -u postgres psql -c "CREATE DATABASE instinct_db OWNER hub_user;"
PGPASSWORD=<пароль> pg_restore -h localhost -U hub_user -d instinct_db --no-owner <файл>.dump
npm run migrate
pm2 start all
```

## Переезд на новый сервер

1. Выполните шаги 1–5 из [DEPLOY.md](DEPLOY.md), `.env` возьмите из менеджера паролей.
2. Вместо пустой базы восстановите последнюю копию (команда `pg_restore` выше), затем `npm run migrate`.
3. Если домен изменился, обновите адрес вебхука в amoCRM и заново выполните `scripts/cdek-subscribe.js`.
4. Запустите `./scripts/healthcheck.sh`.

## Если копии нет

Хаб запускается с пустой базой. Справочники IIKO и фулфилмента подтянутся скриптами. Сопоставление товаров придётся заполнить заново. Сделки, которые были в работе, хаб не помнит. Чтобы вернуть сделку под управление, переведите её снова на этап «Передать в доставку»: перед созданием заявки хаб ищет в СДЭК заказ с номером сделки и, если он есть, подхватывает его, а не создаёт второй.

## Что делать с необработанными событиями

Панель → «Операции» → статус `dead`. В колонке «Ошибка» причина. Исправьте её (чаще всего это несопоставленный товар или недоступная система) и нажмите «Повторить».
